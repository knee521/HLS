## 4 系统架构与实现边界

```text
电脑
  28×28逻辑画板 → 前景裁剪与重心居中 → 784字节图像
       ↓                                       ↓
  原图/处理图预览                      组帧、CRC、序号、计时
                                               ↓ USB UART
FPGA  uart_rx → frame_parser → 784字节图像RAM → HLS nn_infer
                                                  ↓
                          结果锁存 ← digit、done、计算周期计数
                            ↓                 ↓
                    数码管 + LED      response_builder → uart_tx
                                                           ↓
电脑                           校验回包、核对序号、显示结果、CSV
```

FPGA不需要CPU、DDR、操作系统、AXI DMA或外部模型加载。权重编译进HLS ROM；图像使用片内RAM。电脑可以保留离线对照模型，但正常识别按钮必须显示FPGA回包结果，不能用电脑模型输出代替硬件推理。

| 模块 | 输入和输出 | 责任 |
|---|---|---|
| 训练与导出 | MNIST→权重、量化配置、测试向量 | 自行训练、可复现、权重顺序固定 |
| GUI与协议库 | 手写或784字节文件→请求；响应→结果 | 预处理、单请求、序号、计时、保存 |
| uart_rx/uart_tx | 串行位流↔8位字节及valid/ready | 位采样、停止位检查、收发状态机 |
| frame_parser | RX字节→RAM写地址/数据、frame_valid | 长度检查、CRC、超时、重同步 |
| 图像RAM与控制器 | 解析器写入；HLS读取 | 所有权切换、禁止覆盖、启动与超时 |
| nn_infer | image[784]→4位类别 | 纯定点全连接计算及argmax |
| 结果与回包 | digit、cycles→显示及响应字节 | 结果保持、响应CRC、序号回显 |

首版只允许一个在途请求：电脑发一帧，收到匹配结果或超时处理结束后才发下一帧。无需双缓冲与跨帧流水；将复杂度用于数值一致性与错误恢复。所有RTL工作在同一个50 MHz时钟域，UART输入用两级同步；按键复位采取异步置位、同步释放的内部复位策略。

## 5 训练与图像预处理

### 5.1 网络和训练设置

网络为`Flatten(28×28) → Linear(784,32) → ReLU → Linear(32,10)`。输出是10个logit，推理用argmax；交叉熵训练直接接logit，不先做Softmax。

参数数目为`784×32+32+32×10+10=25450`；每张图有`784×32+32×10=25408`次乘加。32个隐藏节点足以作为小型基线，且权重与计算规模便于片内实现；其实际准确率必须由训练证明。本项目不引入CNN、预训练模型、BN或Dropout部署。

初始可复现配置：固定随机种子2026；原始60000张训练数据划分55000训练、5000验证，保存划分索引；batch size=128；Adam学习率0.001；先训20个epoch，按验证准确率选择checkpoint。保存每轮loss、训练/验证准确率、耗时与配置。若未达门槛，先检查标签、归一化和数据流程，再考虑增加训练轮数或在训练集加入轻微平移增强，保持网络结构不变并记录变更。

10000张官方测试集用于最终评估，不用于选择epoch、量化比例或调整预处理。若首次最终评估失败，需要重新开发并再次评估时，明确记录这一事实，不把反复使用的测试集描述成完全未接触数据。

### 5.2 输入数值统一

训练、Python参考、C仿真与硬件统一规定：原始像素`p∈[0,255]`，模型实数输入为`x=p/256`。这样FPGA只存uint8像素，不执行除法，其隐含小数位数为8。白色是255/256，不是1；这不是错误，而是所有环节共同采用的定义。

不要直接使用默认将像素除以255的预处理后又在硬件按256解释。若使用`ToTensor()`，需再乘`255/256`，或者直接由uint8数组转浮点后除以256。不得额外套用MNIST均值方差归一化，除非重新定义并验证全部量化公式。

### 5.3 画板到784字节的确定流程

1. 保存28×28灰度逻辑画布，界面可按10倍显示为280×280；鼠标坐标映射回28×28，默认笔刷宽度约2个逻辑像素，移动点间连续插值，避免断笔。黑背景0、白笔255，可保留边缘灰度。
2. 清空时置全0。发送前按灰度阈值16寻找前景包围框；若无前景，提示“请先书写”，不发送随机分类请求。
3. 裁剪前景，等比例缩放，使最长边为20像素，短边至少1像素；采用固定的双线性插值。不得拉伸成正方形，避免改变数字比例。
4. 放入28×28黑底中心，按灰度质量计算重心：`cx=Σ(x·p)/Σp`、`cy=Σ(y·p)/Σp`。将重心移向(13.5,13.5)，平移量四舍五入为整数。使用零填充，禁止循环移位；若平移会裁掉前景，缩小平移量并记录该边界情况。
5. 转回uint8，按从上到下、每行从左到右排列：`index=y×28+x`。保存处理后PNG、784字节`.bin`及完整请求`.frame`。GUI并列展示原图与最终发送图。
6. 训练/验证/测试的正式MNIST精度使用标准MNIST28×28像素和同一`/256`数值归一化；GUI新增几何预处理用于使现场手写接近MNIST分布。另做“同一图像经GUI几何流程”的一致性/准确率检查，独立报告，不能偷偷更换官方测试口径。

重心居中的目的，是减少手写位置偏移与MNIST分布之间的差异，不是保证任何笔迹都能识别。预演时至少覆盖0–9、不同大小、左右偏移、两位书写者，保留误识别样本。不要以手工挑选5张漂亮样本代替现场测试。

## 6 定点量化方案与数值边界

### 6.1 类型与缩放

首版采用8位输入、8位有符号权重、8位无符号隐藏激活、32位有符号偏置与累加。采用整数加乘、移位和饱和表达定点，便于逐位比对。

| 张量 | 类型 | 对应实数 |
|---|---|---|
| 输入P | `ap_uint<8>` | P×2^-8 |
| 第一层W1q | `ap_int<8>`，限定[-127,127] | W1q×2^-Fw1 |
| 第一层B1q | `ap_int<32>` | B1q×2^-(8+Fw1) |
| 隐藏Hq | `ap_uint<8>` | Hq×2^-Fh |
| 第二层W2q | `ap_int<8>`，限定[-127,127] | W2q×2^-Fw2 |
| 第二层B2q | `ap_int<32>` | B2q×2^-(Fh+Fw2) |
| 输出Zq | `ap_int<32>` | Zq×2^-(Fh+Fw2) |

每一层权重共享一个缩放因子，输出10类共享同一个尺度，因此直接比较Zq即可，不需Softmax或各通道反量化。权重按`[输出节点][输入节点]`存储，与PyTorch Linear权重形状一致，导出时不要额外转置。

### 6.2 量化参数确定

1. 对每层权重找最大绝对值M，初选`Fw=floor(log2(127/M))`，并限制在0至15。M=0时取15。通过实际量化检查范围；若M>127或边界产生饱和，拒绝导出，调整训练或位宽，不能静默截断。
2. 用固定的训练校准子集，例如训练集中6000张，收集ReLU后激活最大值Hmax。初选`Fh=floor(log2(255/Hmax))`并限制到0至15；Hmax=0视为模型异常需检查。再限制`Fh≤8+Fw1`，使右移位数非负。
3. 在5000张验证集上评估邻近的Fh选择及定点准确率，统计激活上溢饱和次数；目标饱和比例≤0.1%，但最终以准确率门槛为准。缩放选择完全由训练/验证数据完成。
4. 权重和偏置的离线舍入统一为“最近整数，正负半值远离零”：`round_sym(x)=sign(x)×floor(abs(x)+0.5)`。不要混用Python内置round的半偶舍入。`B1q=round_sym(b1×2^(8+Fw1))`；`B2q=round_sym(b2×2^(Fh+Fw2))`。
5. 导出`quant_config.json`，写入Fw1、Fw2、Fh、位宽、舍入、饱和策略、校准索引、输入尺度、权重布局、模型哈希和预处理版本。导出脚本应验证全部约束，失败返回非零退出码。

### 6.3 推理的精确定义

```text
A1[j] = B1q[j] + Σ(i=0..783) P[i] × W1q[j][i]
R = 8 + Fw1 - Fh
若 A1[j] ≤ 0：Hq[j] = 0
否则：R=0时取A1[j]；R>0时取(A1[j] + 2^(R-1)) >> R
随后饱和到[0,255]，再转为8位无符号数
Zq[k] = B2q[k] + Σ(j=0..31) Hq[j] × W2q[k][j]
digit = 最小的满足Zq[k]为最大值的k
```

argmax必须从`Zq[0]`初始化最大值，仅遇到严格更大值才更新；不能从0初始化，否则全负输出会出错。隐藏层加舍入常数先扩为33位，避免32位正数加常数溢出；先比较255和饱和，再缩为8位，禁止先强制转换后饱和。

输入uint8不能直接强转为有符号8位参与乘法。先转成能表示0–255的`ap_int<9>`，与8位有符号权重相乘；乘积至少用17位有符号表示，再扩展到32位累加。Python整数参考使用int64中间量并显式执行相同舍入/饱和，不依赖NumPy uint8默认溢出。

### 6.4 累加位宽证明

采用包含-128的保守界限，第一层乘积和的最大绝对值不超过`784×255×128=25589760`；第二层不超过`32×255×128=1044480`。32位带符号范围为[-2147483648,2147483647]，但仍必须把偏置算进去。

每个神经元用int64验证：`abs(Bq)+Σ(max_input×abs(Wq))≤2147483647`，其中max_input=255。这给出所有输入像素及隐藏激活取值下的保守安全界限，而不是仅在测试样本上“没看到溢出”。同时检查偏置能放入32位，隐藏层右移数`0≤R≤30`。任何一项不满足则导出失败。

若8位权重量化损失超标，先查尺度、转置、符号、舍入和预处理，再用验证集调整尺度。仍失败时可将权重改为16位、累加改为40位并重做预算、仿真和综合；网络仍保持784→32→10。该变更应形成新的方案版本，不是跳过既定门槛。

### 6.5 精度与一致性证据

冻结模型后对同一10000张测试图生成三套结果：浮点模型、Python整数参考、HLS C。记录样本编号、标签、三个预测、整数分数与是否一致。报告给出准确率、量化绝对/相对损失、混淆矩阵、典型误判和饱和统计。

**量化误差与实现错误分别判断：** 浮点与定点允许门槛内的差异；Python整数与HLS C不允许同一个输入产生不同整数结果。调试时保存指定样本的A1、Hq、Zq，定位首次分歧层。可在同一HLS源码中增加仅仿真使用的调试导出，禁止用另一套简化C算法替代实际综合函数参加10000张测试。

## 7 HLS实现与资源规划

### 7.1 顶层与接口

顶层原型约定如下，实际生成端口名称、位宽和时序以2018.3综合产物为准，RTL适配器据此连接：

```cpp
#include <ap_int.h>
ap_uint<4> nn_infer(const ap_uint<8> image[784]);
```

顶层使用`ap_ctrl_hs`控制，image使用`ap_memory`读取接口，并约束为单读端口RAM、读取延迟1拍。RTL图像缓冲可采用简单双口RAM：解析器写端口，HLS读端口；容量至少1024×8，合法图像地址仅0–783。不要给每个像素做独立顶层端口，也不使用需要处理器配置的AXI-Lite。

控制器在CRC通过、全部784字节已写入且核心空闲后请求启动；按照`ap_start/ap_ready`完成一次握手，再拉低start，防止自动重复推理。`ap_done`有效时锁存`ap_return`和周期计数。复位信号的名字与极性从导出RTL核对，不能假定一定为`ap_rst_n`。

核启动到结束期间锁定图像缓冲；忙时收到的字节可以丢弃，但不得写入正在使用的图像。回包发送完成后释放事务，重新搜索帧头。内核20 ms看门狗超时时复位核心控制、解除锁定，返回错误状态或由上位机超时处理，系统必须还能接收后续合法请求。

### 7.2 低资源基线

第一层外循环32个神经元，内循环784个输入串行累加；第二层外循环10类，内循环32个隐藏激活串行累加。固定数组、固定循环边界，权重声明为编译期常量并映射为ROM，禁止动态内存、递归、STL容器、运行时文件读取进入综合函数。

对内层MAC循环提出`PIPELINE II=1`请求，不展开全部输入维度，也不对权重数组做complete partition。输入可以先从外部RAM读入局部784字节缓冲，再用于所有隐藏节点；必须把这段读取时间纳入核延迟。层间按顺序执行，不要求DATAFLOW。

**II必须分清粒度：** MAC循环II=1表示每周期可以发起一次循环迭代，不代表每周期推理一张图。整帧启动间隔接近整帧执行时间；分别记录循环II、顶层Interval和Latency。若累加反馈或ROM端口导致真实II=2或更大，先接受真实报告并检查5 ms目标；需优化时可做少量交错累加或小因子展开，重新证明数值和端口足够。禁止用虚假的DEPENDENCE声明掩盖真正的数据依赖。

## 8 串口协议与异常恢复

### 8.1 请求帧

采用二进制定长图像载荷协议。所有多字节整数用小端；CRC本身也低字节先发。序号为16位，电脑每个新请求加1并按65536回绕；同一时刻仅允许一个待响应请求。

| 字节偏移 | 长度 | 内容 |
|---:|---:|---|
| 0–1 | 2 | 帧头A5 5A |
| 2 | 1 | 版本01 |
| 3 | 1 | 类型01，表示图像识别 |
| 4–5 | 2 | seq，uint16，小端 |
| 6–7 | 2 | payload_len=784，即10 03 |
| 8–791 | 784 | 28×28 uint8像素，行优先 |
| 792–793 | 2 | CRC16，小端 |

总长794字节。CRC采用CRC-16/CCITT-FALSE：多项式0x1021，初值0xFFFF，输入/输出不反射，结果异或0，覆盖偏移2–791，即版本、类型、序号、长度及全部图像，不包含帧头和CRC本身。标准检查串ASCII `123456789`得到0x29B1。

具体协议自测向量：序号0x1234、784个全零像素，请求前8字节为`A5 5A 01 01 34 12 10 03`，最后CRC两字节为`1D 88`。这是协议测试，不代表空白图像有合法手写标签。

选择理由：帧头利于扫描，版本和类型阻止误解析，明确长度阻止越界，CRC可检测常见传输错误，序号避免把旧回包记为新结果。固定长度载荷使像素中出现A5 5A也不需转义；代价是断帧后必须靠超时和后续帧恢复，不能声称任意噪声条件下绝不误判。

### 8.2 响应帧

响应也使用相同8字节头和2字节CRC，类型为81，payload_len=7，总长17字节。

| 载荷偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 1 | status：00成功，01推理看门狗超时 |
| 1 | 1 | digit：成功时0–9，错误时FF |
| 2 | 1 | flags：本版本固定00，保留 |
| 3–6 | 4 | inference_cycles，uint32小端 |

seq原样回显请求序号。周期计数定义为控制器确认本次启动到捕获本次done之间经过的50 MHz时钟周期数，包含HLS输入读取和推理，不含UART收帧。计数规则在RTL仿真中用已知延迟核心验证，避免差一个周期。它与HLS静态Latency可能因接口握手相差少量周期，应解释差异。

响应例子：序号0x1234、成功、数字7、计数25408，完整字节为：

```text
A5 5A 01 81 34 12 07 00 00 07 00 40 63 00 00 EA F5
```

此例为人工构造的协议向量，不是模型或硬件实测结果。请求CRC错误、版本/类型不支持、长度错误或UART停止位错误时，首版直接丢弃，不产生可能携带错误seq的NACK；上位机通过500 ms事务截止判定失败。

### 8.3 UART实现

采用整数分频，每位时钟数取`round(50000000/baud)`。起始位下降沿后在半位位置复核低电平，然后逐位在中心采样，低位先传；最后检查停止位为高。RX同步器与数据路径保持独立，不能让GUI开关或解析状态影响位采样。

| 标称波特率 | 分频N | FPGA实际波特率约值 | 相对误差 |
|---:|---:|---:|---:|
| 115200 | 434 | 115207.37 | +0.0064% |
| 230400 | 217 | 230414.75 | +0.0064% |
| 460800 | 109 | 458715.60 | -0.4523% |
| 921600 | 54 | 925925.93 | +0.4694% |

每个速度分别编译/配置FPGA与上位机，二者一致后测试。不能仅凭误差小就断言USB桥、驱动和线缆一定稳定。首版不实现运行时切波特率命令，避免通信速率切换过程产生额外状态。

### 8.4 解帧状态机

状态建议：`SEARCH_A5 → SEARCH_5A → HEADER → PAYLOAD → CRC → START → INFER → TX`。

1. 搜索中收到A5后等待5A；若又收到A5，保留新的候选帧头，以正确处理`A5 A5 5A`。
2. 头部完整后验证版本、类型及长度。长度必须等于784；任何其它值立即弃帧，绝不据长度分配存储或越界写RAM。
3. 接收784个载荷字节，地址计数器至少10位，写入范围检查0–783；即使载荷内有帧头也按像素处理。接收同时更新CRC。
4. CRC通过后才置`frame_valid`并启动推理。CRC失败时当前RAM内容视为无效，下一帧覆盖；不改变有效显示结果。
5. 接收帧期间设50 ms字节间超时，以及从帧头起250 ms整帧绝对超时。50 MHz下分别为2500000和12500000周期，计数器至少22位和24位。超时、UART framing error或复位使解析器回到搜索态。
6. `INFER/TX`期间丢弃额外输入，不改写图像，不重复启动。发送完响应的停止位后，释放事务并重新进入搜索态。GUI遵守单在途请求，不依赖忙时的吞吐能力。
7. 噪声可能形成假帧头并消耗后续字节，因此保证的是“噪声停止后，经限定恢复等待能继续工作”，不是“插入任何垃圾后紧随的第一帧必定成功”。恢复测试必须包含这一区别。

CRC16是错误检测机制，不是对所有乱码的绝对证明。测试应覆盖长度、序号、超时和校验组合，而不是只做一次翻转字节测试。

## 9 上位机功能和时间口径

### 9.1 必须实现的界面功能

界面包含：串口选择、波特率选择、连接/断开、黑底白字画板、清空、发送图预览、保存784字节及帧文件、载入帧/图像文件、发送识别、FPGA结果、当前耗时、累计正确/错误与CSV保存。

保存完整帧文件时保留其seq；重新发送文件应取出图像、重新分配seq并重算CRC，避免旧序号混淆。命令行批量工具与GUI复用同一个`protocol.py`和`preprocess.py`，不要各写一份逻辑。

串口收发放工作线程，GUI只通过消息队列更新。连续点击发送时禁用按钮或提示忙，不可并发写串口。连接成功后只在开始实验前清空一次旧输入；每帧发送后不得清空接收缓冲，否则可能丢掉很快返回的有效响应。

serial采用有限`timeout`和`write_timeout`，接收缓冲累积字节并循环解析。一次`read(17)`不保证返回17字节，高速波特率也不是所有端口都支持，应显式处理短读与异常。[pySerial读写和波特率说明](https://pyserial.readthedocs.io/en/latest/pyserial_api.html)

### 9.2 端到端时间

使用`time.perf_counter_ns()`。在完整帧已生成、即将调用第一次串口write前记录t0；收到完整响应，版本、长度、CRC及seq全部验证成功时记录t1：

`T_total_ms=(t1-t0)/10^6`。

这一区间包含write调用、实际传输、FPGA处理、响应传输及操作系统/USB/解析开销；不包含用户画字、图像预处理、模型训练或GUI重绘。不能在`write()`或`flush()`返回后才开始计时，也不能在只收到响应首字节时停止。

写操作检查返回字节数；若不足则继续写剩余部分，t0不重置。每个事务有绝对500 ms截止；错误CRC或其它seq的响应不能结束本次计时。截止时记录失败，恢复接收状态；若启用重试，记录每次attempt和用户级总耗时，失败样本不能从“优化后耗时”中悄悄删除。

### 9.3 传输下限与时间分解

8N1每个字节占10个串行位。对794字节请求及17字节响应，用标称波特率估算：

`T_request=794×10/B`，`T_response=17×10/B`；
`T_total=T_request+T_core+T_response+T_other`。

这里是协议各段顺序执行时的工程分解；UART实际分频、USB批量传输及主机调度会产生偏差。`T_core=inference_cycles/50000000`。用总时间减去其余已知项得到的`T_other`只能称“残余开销估计”，不能假装把USB、调度和解析分别实测出来。

| 波特率 | 请求估算ms | 响应估算ms | 纯串口合计ms |
|---:|---:|---:|---:|
| 115200 | 68.9236 | 1.4757 | 70.3993 |
| 230400 | 34.4618 | 0.7378 | 35.1997 |
| 460800 | 17.2309 | 0.3689 | 17.5998 |
| 921600 | 8.6155 | 0.1845 | 8.7999 |

表中均为公式估算，不是优化效果实测。即使推理只耗约0.5 ms，115200下总时间仍受约70.4 ms的串口开销支配。因此先优化波特率通常比扩大乘法器数量更值得验证；是否成立最终由实测表判断。

### 9.4 逐帧日志字段

`timestamp, run_id, config_id, model_sha256, bit_sha256, baud, seq, sample_id, image_sha256, source, label, prediction, status, crc_ok, matched_seq, inference_cycles, total_ms, attempt, error_reason`。

label未知时留空，不默认判对。GUI显示的时间必须来自同一条已保存记录。批量统计同时报告样本数、成功率、准确率、均值、中位数、P95、最小和最大值。P95统一采用将成功样本耗时升序排列后的第`ceil(0.95×N)`项，注明不含失败请求的延迟分位数，并另列失败数与超时耗时。

## 10 分阶段实施与放行条件

以下顺序落实“先方案、后代码；先UART、再解帧、再推理、再完整显示”。耗时由实际进度决定，不以赶时间替代阶段验证。每一关都保存日志及版本；失败先回到最近通过版本，仅修改一个原因再重测。

### G0 资料冻结和工程骨架

输入：R1至R7、本文件、实际工具与硬件信息。输出：项目简报、配置清单、文件结构、原始资料哈希及第一条T2日志。确认本文件的方案和目标后，建立第16节规划目录。

放行：板卡、器件、时钟、全部引脚、工具绝对路径、串口、电源、验收八项均明确；型号或接线有疑点时不得进入硬件下载。保留原始资料，不覆盖模板。

### G1 时钟复位和UART回环

先由AI生成最小RTL、testbench、仿真Tcl和Vivado创建脚本。仿真覆盖00、FF、55、AA、连续字节、停止位错误和不同起始相位。上板发送00–FF序列至少10轮并逐字节比较；正常流量不能丢字节、重字节或改变顺序。FIFO/缓冲在相同速率回环中必须有明确的满/空处理，不能假设TX永远立即ready。

同时运行显示自检，完成物理最右位映射。放行证据为UART波形、2560字节回环统计、COM与连接照片、显示测试记录。此时不接神经网络，避免把串口故障误判为模型问题。

### G2 解帧和受控结果回包

实现第8节协议；先用明确标记为测试模式的固定digit或小校验逻辑代替核心，验证从GUI/CLI到CRC、RAM和回包的路径。对接收的784字节逐地址比对，与请求一致；覆盖CRC、超时、长度错误、垃圾前缀和载荷内帧头。

放行：正常请求得到匹配seq的有效响应；错误请求不启动核心、不更新显示；噪声停止后合法请求能恢复。**测试桩仅用于接口联调，最终验收bit必须移除。**

### G3 浮点模型训练

实现训练、验证和离线评估脚本，保存种子、划分索引、依赖版本、checkpoint和模型哈希。检查输入为`/256`，权重确为784→32→10。验证集选择最佳checkpoint后冻结，进行正式测试。

放行：完整训练记录存在，浮点测试准确率达到第2节门槛；错误样本可追溯。若不达标先检查实现和训练，不以“网络简单”为由降低既定标准。

### G4 定点导出和完整C仿真

实现量化导出、Python整数参考及HLS顶层，导出10000张图和标签、整数参考分数。C测试程序直接调用待综合的`nn_infer`；测试程序错误必须返回非零，不仅打印字符串。阶段顺序为：少量逐层比对→所有10000张比对→准确率统计→保存通过记录。

放行：位宽证明成立，定点准确率和相对/绝对损失达标，10000张整数结果一致；模型、权重头文件及参考结果之间的哈希对应关系清楚。

### G5 HLS综合和RTL协同仿真

执行C仿真、C综合，检查器件、20 ns、Latency、顶层Interval、内循环实际II及资源。按第7节的小规模固定清单进行cosim，包含至少两笔连续事务，验证控制握手及重复启动行为。

放行：cosim全部通过，无数组越界或未初始化行为；目标器件正确；DSP满足预算；5 ms目标达成或有清晰整改措施，整改后再放行。导出IP能够成功，并保存准确的导出目录、版本、全部ROM文件与日志。

### G6 Vivado整机集成和实现

将已验证协议、图像RAM、HLS核、计数器、数码管与LED接入顶层。先做整机RTL仿真，以至少10个已知图像覆盖0–9及全部事务流程，核对响应、显示锁存值和输入缓冲所有权。

新建Vivado工程，设置`xc7a35tfgg484-2`，加入源码、HLS IP和最小XDC。综合、实现、生成bit；保存`report_utilization`、`report_timing_summary`、`report_drc`与`report_cdc`。异步UART仅在同步器入口按实际设计做针对性例外；禁止用整片false path或降低时钟约束掩盖内部时序失败。

放行：50 MHz内部同步路径WNS≥0、TNS=0；不存在未处理的严重DRC或未约束内部时钟路径；检查同步器与复位释放；DSP≤60，资源符合器件容量及预算。若预算预警超出，先优化或记录经审阅的预算调整，DSP≤60不能调整。

### G7 上板全链路

按第11节下载bit，先用已知文件输入验证，再用现场手写。放行：至少100张固定文件的FPGA预测与HLS C完全一致，并完成20次跨书写者的手写预演。100张文件不要求全部分类正确，要求与同一整数模型结果一致；分类准确率另行记录。

### G8 健壮性与优化

完成第12节全部异常用例，执行第13节至少一项真实优化。冻结最快稳定版本，重复其正常输入与错误恢复测试。放行：保留优化前后bit、配置、CSV和资源表，能现场切换或复现实验，不能只有估计数字。

### G9 报告和验收归档

独立撰写8页报告，填写AI声明，准备原始日志和验收记录表。按第14节自检，再由教师验收签字。未通过时保存问题、整改动作和复验记录；按R5在课程结束前完成允许的一次整改验收。

## 11 上板操作规程

1. 核对本次`config_id`、模型SHA256、权重头文件SHA256、bit SHA256及UART速率。打包时建立manifest，避免训练用新权重而板上仍为旧bit。
2. 打开Vivado Hardware Manager，连接JTAG目标，确认识别的芯片与工程一致；选择本次bit后Program Device。只有确实使用ILA时才加载对应.ltx。
3. 按复位，检查约1秒显示自检、空闲显示与LED初值。先使用已确认的COM端口和115200，串口调试助手与GUI不可同时占用端口。
4. 发一张已冻结的数字文件，逐项核对：请求seq、响应CRC、digit、核心周期、GUI耗时、物理最右数码管、LED二进制值。
5. 用100张固定测试文件批量发送，每次收到结果才发下一张，生成`board_compare.csv`。若出现不一致，优先检查RAM读取延迟、ROM装载、复位、符号与启动握手，不先重新训练模型。
6. 手写0–9至少各一次，并由另一位书写者重复；保存处理后图、标签、回包与耗时。预处理调整后必须重新跑相关离线和板上回归，记录版本变化。
7. 运行错包测试；成功后换优化速率对应bit并在GUI同步修改波特率，重新连接后验证。
8. 验收前重新上电/下载一次最终版本，按归档步骤恢复现场，证明无需依赖未保存的IDE状态。

## 12 健壮性测试矩阵

正常有效帧应只启动一次推理；所有非法或不完整帧不应更新有效识别结果。每种测试记录原始发送字节、时间、预期、实际、是否自动恢复。以下为计划用例，不是已发生的故障记录。

| 用例 | 注入方式 | 合格判据 |
|---|---|---|
| 正常帧 | 固定图像和seq | 单次启动，响应CRC正确且seq相同 |
| 错CRC | 图像翻转1位但不改CRC | 不启动；后续合法帧可恢复 |
| 错长度 | 长度改0、783、785、FFFF | 不越界写，不等待巨大长度，不启动 |
| 错版本/类型 | 版本02或类型7F | 丢弃，不破坏下一次正常事务 |
| 截断头/载荷/CRC | 在多个偏移停止发送 | 达超时后退出；无需复位即可接下一帧 |
| 垃圾流 | 固定种子随机字节，包含A5与5A | 有界状态，不死锁；停发300 ms后恢复 |
| 重叠帧头 | A5 A5 5A后接合法头体 | 正确识别后一个A5 5A |
| 载荷含帧头 | 图像中插入多个A5 5A并重算CRC | 当作像素，按784字节计数 |
| UART停止位错 | RTL仿真强制停止位低 | 丢弃当前帧并重同步 |
| 忙时额外请求 | 在推理或响应期间注入另一请求 | 不覆盖RAM、不污染当前结果；额外帧允许丢弃 |
| 软件短读 | 将响应按1、2、3字节分片交给解析器 | 可累计并正确解析17字节完整响应 |
| 旧序号/错响应CRC | 向上位机注入旧响应或坏响应 | 不结束当前计时，不误更新结果 |
| 中途复位 | 接收、推理、TX三个状态分别复位 | 清理事务，下一次完整请求可成功 |
| 核超时 | 仿真让测试核不产生done | 20 ms看门狗释放系统，后续合法事务可执行 |
| 串口断开重连 | 等待响应时拔插或关闭端口 | GUI不冻结，有错误提示，重连后可使用 |

硬件UART物理层错误不一定能由普通串口库直接制造，停止位错误至少在RTL仿真覆盖；现场重点演示随机乱码、错误CRC及截断帧，再发合法图像。不要把仿真测试标成上板实测。

## 13 优化实验和数据表

### 13.1 第一项优化 提高UART波特率

基线A固定115200，候选B先230400，再460800；921600作为稳定后选项。模型、权重、预处理、测试图像、帧长、主机、USB口和推理核保持一致，只改变通信速率与对应分频参数。保存基线bit及配置，不覆盖唯一可用版本。

每个配置先10帧预热，再用同一套100张图测3轮，共300次正式请求；统计全部请求的成功率与耗时。候选配置还须通过第12节异常恢复，并进行至少1000次合法请求稳定性测试，要求该次测试零丢帧、零CRC错误、零超时。该结果只证明测试条件下稳定，不宣称长期错误率绝对为零。

至少有一项优化在真实硬件上测得正向效果才可填“完成”。若提速后不稳定，回退一级；若所有提速候选失败，转做推理调度优化，并仍提供前后实测。不得只列出理论节省时间作为R1要求的“优化实测”。

### 13.2 第二项可选优化 HLS调度

仅在测得核心时间确有占比或首版未达到5 ms时推进。每次只变一个因素，例如内层PIPELINE，或展开因子从1调整为2/4。展开时同步分析ROM端口带宽和累加结构，禁止直接展开784次。按要求记录方案提出与验证两类交互，并重跑整数一致性、cosim、资源和时序。

MAC变快不必然显著降低端到端时间，报告应解释收益为何受串口上限限制。不能为了降低HLS延迟牺牲现场准确率或超过DSP预算。

## 17 故障排查和可行性边界

| 现象 | 首查证据 | 修复方向及复验 |
|---|---|---|
| UART无回包 | COM、TX/RX、地线、波特率、RX波形 | 回到G1回环，通过后再接解析器 |
| 收到乱码 | 实际分频、位采样、8N1、同步器 | 先回退115200，检查时钟是否50 MHz |
| C与Python整数不一致 | 首个分歧的A1/Hq/Zq、权重布局 | 检查符号扩展、舍入、饱和和bias尺度 |
| C通过但板上结果错 | RAM地址/延迟、ROM初始化、核握手、bit哈希 | 用同一固定图像及ILA/仿真定位，避免先改模型 |
| 数码管全灭或乱码 | 段码顺序、低有效、物理位号 | 逐段逐位测试，保存RIGHTMOST_INDEX |
| 现场识别差而MNIST达标 | 实际发送的28×28图、笔宽、重心 | 检查前景极性、缩放与居中，保存误判样本 |
| DSP或BRAM暴涨 | 展开、partition、ROM映射和乘法器实例 | 回到串行基线，逐项增加并行度 |
| HLS II未达到1 | 调度报告中的反馈依赖与端口冲突 | 按实测接受或小幅重构，禁止虚假依赖消除 |
| 整机时序失败 | 实现WNS、关键路径、扇出、复位 | 降并行度或分段流水，重新实现验证 |
| 计时比传输下限还短 | t0位置、停止条件、旧seq、单位 | 在write前计时，完整有效回包后停止 |
| 延迟偶发很大 | 丢包/重试、USB调度、串口读超时、GUI阻塞 | 用原始逐帧日志定位，避免只报最小值 |
| 错包后不再工作 | 超时计数、busy释放、长度边界 | 重放最小错误字节流，检查恢复状态机 |
| 导出IP失败 | 完整HLS日志及core_revision报错 | 核对AR76960补丁与2018.3兼容性 |

**可行性结论：** 该方案只需两个全连接层、25576字节即约24.98 KiB的权重与偏置、25408次MAC、单帧片内缓存和UART/数码管等既有外设，规模与所选器件及DSP≤60约束相容；串行乘加与单在途事务降低了资源和接口复杂度。这个结论是基于计算规模、已核对资料与接口设计的工程判断，不替代实际综合和上板证据。最终放行取决于G0至G9，尤其是量化精度、整数一致性、50 MHz时序、实际接口兼容性和现场笔迹识别表现。

## 附录A CRC参考定义

下面代码只定义协议校验，可作为后续Python及RTL CRC测试的参考。编制本文时已核算第8节的请求和响应示例。

```python
def crc16_ccitt_false(data):
    crc = 0xFFFF
    for byte in data:
        crc ^= byte << 8
        for _ in range(8):
            if crc & 0x8000:
                crc = ((crc << 1) ^ 0x1021) & 0xFFFF
            else:
                crc = (crc << 1) & 0xFFFF
    return crc

assert crc16_ccitt_false(b"123456789") == 0x29B1
# 帧CRC尾部：crc.to_bytes(2, "little")
```
